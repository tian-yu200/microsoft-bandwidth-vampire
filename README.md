# 你的电脑是微软的免费分发节点——Windows"传递优化"实测记录与彻底关闭指南

> 本文全部数据来自 2026-11-11 深夜的一次真实故障排查。作者本是去破解一台随身 WiFi，结果顺手抓到了 Windows 在用户毫不知情时把电脑变成公共上传节点的现行——那晚它替互联网上的陌生人们"发了一晚上快递"，运费记在作者的蜂窝流量卡上。

## TL;DR

- Windows 的**传递优化（Delivery Optimization）**默认以"互联网模式"运行：你的电脑会**向互联网上不认识的电脑上传 Windows 更新碎片**。这不是 bug，是默认设置。
- 你就算**手动停用了 Windows 更新**，这个上传引擎（DoSvc 服务）依然独立运行、照常分享。
- 普通流量监控里它几乎隐身；只有把"网络属性→按流量计费"手动打开，它才会收敛——而"按流量计费"这个开关，微软埋得很深。
- 文末有**实测有效的完整关闭方案**（含撤销方法），全部命令可复制粘贴。

## 一、事情是怎么败露的

作者的电脑通过一台随身 WiFi（蜂窝流量卡，联通 LTE）上网。某天深夜发现流量卡"两天掉了 2GB"，遂起了疑心。排查过程：

1. 登录随身 WiFi 管理后台，读取设备自己的流量计数器：**当晚实耗约 0.58GB**，且还在以 **约 34MB/分钟** 的速度持续增长——折算下来是持续不断的约 2.3Mbps 上行流量。
2. 电脑侧 `Get-NetAdapterStatistics`：20 分钟内 **上传 151MB**、下载 75MB。上传比下载还大，这绝不是"正常上网"。
3. 凶手现场落网：

```powershell
PS> Get-DeliveryOptimizationStatus

内容                                Status  已下载MB  总大小MB
----                                ------  --------  --------
WU Client Download                  Caching        0        0
WU Client Download                  Caching        0        0
（共 19 个任务，全部处于 Caching 状态）
Microsoft Component Updater DO Job  Caching        0        0
```

**19 个更新缓存任务**，状态 `Caching`——翻译成人话：*本机已下载好 Windows 更新碎片，正在等待并持续向互联网上的其他电脑分发*。

4. 关闭传递优化的 P2P 共享后复测：**75 秒仅消耗 105KB**（约 5MB/小时），对比关闭前的 2GB/小时级别，天壤之别。

## 二、这套机制"丑"在哪

先说清楚，避免恐慌：**上传的内容是微软签名的更新文件碎片，不是你的个人文件、照片或密码**。这一点微软没有撒谎。

问题不在于"传了什么"，而在于"**凭什么**"。以下每一条都有本文实测或官方文档背书：

### 1. 默认把你家电脑当公共分发节点，且没有真正的 opt-in

`DODownloadMode` 默认值是 **2（互联网模式）**——向全网陌生节点上传。这个设置在系统安装时从未明确征求过用户同意，只藏在一层套一层的设置页面和组策略里。微软省下了 CDN 带宽账单，买单的是每一个"默认设置"用户的家庭带宽、电费、以及——对本文作者而言——**按 MB 计费的蜂窝流量**。

### 2. 设置项的名字在撒谎（至少在误导）

设置界面里这个功能的名字叫：**"允许从其他电脑下载"**。

一个普通用户读这句话，理解到的是"我从别人那里下载"。**他永远不会知道这句话同时意味着"其他电脑也在从我这里下载"**。上传方身份被一个以"下载"命名的开关悄悄打包。这不是措辞疏忽——同一页面如果老老实实写"允许你的电脑向其他电脑上传更新文件"，绝大多数用户会立刻关掉它。

### 3. 对"计费网络"毫无感知

Windows 把所有 WiFi/以太网默认当作**不限量宽带**。你用手机热点、随身 WiFi、物联卡上网？它不在乎，照跑。唯一让它收敛的方法是用户**手动**找到 `设置 → 网络和 Internet → WLAN → 点开那个 WiFi → 属性 → 打开"按流量计费的连接"`——一个普通用户一辈子都不会走的五层路径。

顺带一提：手机端（Android/iOS）默认把 WiFi 视为不限量，热点流量被电脑级后台吃光的故事，每一个用过流量卡的人都遇到过。

### 4. "停更"根本停不干净——用户意图不被尊重

作者的电脑**早已手动停用了 Windows 更新主服务（wuauserv）**。实测结果：

| 服务 | 作用 | 作者停更后状态 |
|---|---|---|
| wuauserv | 更新主服务 | ✅ Stopped / Manual（用户操作生效） |
| **DoSvc** | **传递优化（P2P 上传引擎）** | ❌ **Running / Automatic** |
| UsoSvc | 更新协调器 | ❌ Running |

**停更新 ≠ 停分享**。上传引擎是独立服务，你关你的，它传它的。更糟的是，Windows 内置的"修复"机制（WaaSMedicSvc 等）会周期性地把用户手动停用的更新服务改回默认状态——你在和操作系统本人抢方向盘。

### 5. 家庭版用户连官方面板都没有

微软官方文档里控制传递优化的正路是**组策略（gpedit.msc）**——**Windows 家庭版根本没有这个工具**。数量最庞大的用户群，想精细控制只能去写注册表。

### 6. 流量账单上查无此人

任务管理器里它伪装成"服务主机：网络服务"；设置的数据使用量页面里，它的归类和体量展示也不醒目。普通用户对着运营商账单一头雾水，永远不会把嫌疑落到一个以"优化"和"下载"命名的功能头上。

## 三、解决方案（按推荐顺序，全部实测有效）

### 方案 A：一键策略——禁止 P2P 分享（本文采用 ✅）

以**管理员身份**运行 PowerShell：

```powershell
# 1. 策略: 仅 HTTP 直连下载, 禁止向任何人上传/分享
$key = "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization"
New-Item -Path $key -Force | Out-Null
Set-ItemProperty -Path $key -Name "DODownloadMode" -Value 0 -Type DWord

# 2. 重启服务使策略生效
Restart-Service DoSvc -Force

# 3. 清空已缓存的更新碎片
Delete-DeliveryOptimizationCache -Force
```

- **效果**：你自己的更新照常从微软直连下载（如果没被你停掉的话），但**不再向任何节点分享任何字节**。
- **副作用**：微软商店的下载可能变慢（不再走 P2P 加速）——对多数人是无感收益。
- **撤销**：删除该注册表值，或把值改回 `2`，即可恢复默认。

也可以直接用本仓库的成品脚本：[`fix/stop-p2p-node.ps1`](fix/stop-p2p-node.ps1)（等价于上述命令）。

### 方案 B：图形界面十秒版（每个 Windows 用户都该做）

> 设置 → Windows 更新 → 高级选项 → 传递优化 → "允许从其他电脑下载" → **关闭**

或者只关上传部分：同一页面选择"**本地网络上的设备**"——至少别再向全网陌生人开放。

### 方案 C：用蜂窝流量/热点的人必做——按流量计费

> 设置 → 网络和 Internet → WLAN → 点击你正在用的热点 WiFi → 属性 → **打开"按流量计费的连接"**

开了它，Windows 会把这张网当蜂窝卡对待：更新暂停、P2P 停止、云盘收敛。**给每个可能连热点的 WiFi 都开一遍**，这是最后一道闸。

### 方案 D：查证方法（把它抓现行）

```powershell
# 看它在不在传、传什么
Get-DeliveryOptimizationStatus

# 看服务有没有被"医疗队"复活
Get-Service wuauserv, DoSvc, UsoSvc
```

**维护成本提示**：微软的更新修复机制会周期性把用户停用的服务改回默认。方案 A 的注册表策略相对顽固（策略优先级高于默认配置），但建议每隔一段时间用方案 D 复查一眼。

## 四、写在最后

有人会说："P2P 分发是为了大家下载更快，是互利。"

——互利的前提是**自愿**。一个默认打开、名字叫"下载"、藏在五层菜单后面、家庭版没有管理面板、会自动修复被用户关闭的服务的行为，无论包装成多先进的技术方案，本质都是**拿用户的资源去做厂商的成本优化，而不给用户一个说"不"的机会**。至少，不给一个**看得懂**的机会。

在按量计费的蜂窝网络时代还沿用"宽带无限量"时代的产品假设，出事只是时间问题。本文作者的两 GB 流量，就是这份时间差里的一滴水。

你的电脑你做主——至少在打完这几行命令之后，是。
